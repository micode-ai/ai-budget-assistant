# Release notes for admin -> App Versions - 1.28.0

Store / in-app `UpdatePrompt` release notes for version **1.28.0**, one block per
locale. Locales: `en`, `ru`, `ua`, `pl`, `es`, `fr`, `de`, `be`, `nl`.

**Splitting by item leads, and it is written as something that now works rather
than as something new.** 1.27.0's notes announced sharing one item between
several people; that code shipped but was unreachable, because a scanned
receipt's lines never reached the state the split screen requires and it
silently fell back to an equal split. Anyone who read the last release notes
and then tried it saw nothing happen. The honest line is "now actually works",
not "new" — and it is first because it is the thing a user already tried and
failed to do.

**No one is asked to rescan anything.** The fix repairs receipts already on the
phone the moment their split screen is opened, so the notes say so explicitly.
Without that sentence the reasonable assumption is that only new receipts
benefit, and old ones would go unretried.

**The guest flag is described from the payer's side.** The person reading these
notes is the payer, not the guest — what changes for them is that a friend can
now say "this wasn't mine" and they will see it. The guest-facing half needs no
announcement: guests never install the app.

**A minor, not a patch.** The guest flag is new capability, and item splitting
becoming reachable is closer to a feature arriving than to a repair, so 1.28.0
rather than 1.27.1.

---

## en

```
New in 1.28.0:
- Splitting a receipt by item now actually works. Tap an item, then tap everyone who had it — a shared line is divided equally between them. This was announced last release but never worked; receipts already on your phone are repaired the moment you open their split screen, so nothing needs rescanning.
- A friend opening your split link can now flag a line they weren't part of, or their whole share. You see the flag in the app and can resolve it once you've sorted it out.
- Fixed: corrections you make to a receipt's lines after saving are now sent to the server instead of staying on one device.
```
